# New-Mac / disaster recovery — restoring rip-movie

Everything needed to rebuild rip-movie on a fresh machine. Code and config (with `${ENV}`
placeholders) are in git; only the real secrets and the large tool binaries/venv live outside git.

## 1. Prerequisites
```bash
brew install ffmpeg tesseract mkvtoolnix kubectl uv ansible
# MakeMKV (makemkvcon): install from https://www.makemkv.com (needs its license/beta key)
# Cluster access: restore ~/.kube/config for the homelab so kubectl works
```

## 2. Clone
```bash
git clone https://github.com/seadogger/rip-movie.git ~/Desktop/Development/rip-movie
cd ~/Desktop/Development/rip-movie
```

## 3. Restore secrets — `config/secrets.env`
Real API keys / passwords are **not** in git; only the ansible-vault-encrypted copy
`config/secrets.vault.env` is. The vault password lives in your **Passwords app** (and,
on the original Mac, macOS Keychain service `ansible-vault:rip-movie`).

```bash
# re-add the Keychain item from your Passwords-app entry:
security add-generic-password -U -a "$USER" -s "ansible-vault:rip-movie" -w "<vault password>"

# decrypt the backup back into place:
ansible-vault view --vault-password-file config/vault-pass-keychain.sh \
  config/secrets.vault.env > config/secrets.env
```
`secrets.env` provides: `TMDB_API_KEY`, `JELLYFIN_API_KEY`, `NEXTCLOUD_USER`, `NEXTCLOUD_PASS`.

## 4. Rebuild the tools (PyTorch venv + models)
Not duplicated here — follow **[tools/README.md](../tools/README.md)**. In brief:
```bash
uv venv --python 3.11 tools/torchenv
uv pip install --python tools/torchenv/bin/python torch spandrel pillow numpy coremltools opencv-python-headless
# then download + convert the Real-ESRGAN models per tools/README.md
```

## 5. Config
`config/rip-movie.toml` is committed and uses `${ENV}` placeholders fed by `secrets.env`.
`config/rip-movie.example.toml` is the reference; adjust machine-specific paths if needed.

## Notes
- `~/rip-movie` (home-level) holds runtime state/logs/work — regenerated by the pipeline; not needed to restore.
- The HR training dataset lives on Nextcloud, not git.
- After restoring, rotate `NEXTCLOUD_PASS` if it may have been exposed, then re-encrypt:
  `ansible-vault encrypt --vault-password-file config/vault-pass-keychain.sh --output config/secrets.vault.env config/secrets.env`
